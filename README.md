# Системный дизайн: практика — НИУ ВШЭ МИЭМ, 2026/27

## Идея курса

Одна сквозная система — `soldout`, сервис продажи билетов на «дроп» (40 000 мест, 2 000 000 желающих, старт продаж в 12:00). Каждое занятие — один архитектурный шаг: он что-то чинит и что-то ломает. Система эволюционирует от модульного монолита (занятие 1) к распределённой системе с сагами, шардированием и chaos-тестами (занятие 8). Сквозная нить — ИИ-агенты как инструмент архитектора: **спецификация → ADR → генерация → fitness functions → проверка**.

## Формула оценки

`0.1 · семинары + 0.6 · ДЗ (HW1 0.25 + HW2 0.20 + HW3 0.15) + 0.2 · защита постмортема (HW4) + 0.1 · активность`. Теоретического теста нет.

У каждого ДЗ три режима: **full** (полный стенд, ноутбук ≥ 16 ГБ), **lite** (облегчённый профиль, 8–16 ГБ), **аналитический** (без стенда, по выложенным артефактам прогона преподавателя; потолок — 2-й уровень). Критерии всегда трёхуровневые: (1) запустил и получил результат; (2) измерил и объяснил; (3) предложил и проверил решение. Подробности — в `hw/hwN/HW_N.md`.

В отчёте обязателен раздел «Как использовался ИИ» (см. [docs/ai-agents.md](docs/ai-agents.md)). Использовать агентов разрешено и поощряется; оценивается артефакт и понимание.

## Быстрый старт (занятие 1)

Нужны Docker с Compose v2 и `make`. Проверка окружения: `tools/doctor.sh`. Пять команд:

```bash
make up          # поднять стенд занятия 1 (PostgreSQL, Valkey, soldout), ≤ 60 с до readyz
make smoke       # k6: 10 VU × 60 с, seatmap → hold → order → pay
make invariants  # инвариант-чекер I1–I4 по данным в PostgreSQL
make lint-arch   # go-arch-lint: правило зависимостей модулей
make test        # go test ./... (unit + интеграционный через testcontainers)
```

Команды выполняются из корня (`make up` = `make -C soldout up`) или из `soldout/`. Полный список — `make help`.

